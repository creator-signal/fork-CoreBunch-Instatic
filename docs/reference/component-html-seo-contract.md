# Component HTML and SEO contract

This is the published-output contract for the Creator Signal Component Library. It
covers semantic HTML, search metadata, structured data, accessibility,
progressive enhancement, CSS hooks and design tokens. The catalogue registry
continues to own author-facing fields, variants, slots and dependencies.

The contract is normative for implementation and acceptance. A row in this
document does not by itself prove editor, publisher or live-browser completion.

## Output boundary

Published pages use semantic HTML5, generated CSS and small vanilla JavaScript
modules where native HTML is insufficient. They do not ship the editor
application or a frontend component runtime.

Components mode exposes governed content and configuration. It does not expose
implementation markup, arbitrary component classes or internal JavaScript.
HTML mode remains the advanced surface for low-level modules and site-owned
classes.

The implementation must:

- keep authored content separate from the rendered element structure;
- emit the most specific native element that matches the content;
- retain meaningful content when CSS or JavaScript is unavailable;
- use native elements before ARIA and add ARIA only for missing semantics;
- keep headings in the page outline instead of selecting levels for size;
- render one accessible page language on `html` and language changes on the
  affected content;
- escape text and attributes at the rendering boundary;
- permit structured data only when its values describe visible page content;
- deduplicate component CSS and JavaScript by module type;
- keep canvas-only selection attributes out of published output.

## Native CSS contract

Component-owned styling uses Instatic data hooks. It does not depend on copied
component class names.

| Purpose | Published convention |
|---|---|
| Component identity | `data-instatic-component="<kind>"` |
| Approved variant | `data-variant="<variant>"` |
| Interactive state | a component-specific `data-instatic-*` attribute |
| Dynamic binding scope | `data-instatic-binding-prefix` |
| Site-authored styling | ordinary classes stored in the site style registry |
| Generated utilities | framework classes such as `text-*`, `bg-*`, `border-*`, `gap-*` and `padding-*` |

Selectors must use an element or stable data hook, for example:

```css
[data-instatic-component="card"] {
  display: grid;
  gap: var(--space-s);
  padding: var(--space-l);
  border: 1px solid var(--border-primary);
  background: var(--bg-surface);
  color: var(--text-body);
}
```

Component CSS may consume only variables generated by the site framework or a
component-local custom property declared in the same CSS block. It must not
silently rely on an undefined token with a fallback.

| Token family | Published variables |
|---|---|
| Brand | `--primary`, `--secondary`, `--tertiary` and generated variants |
| Surface | `--bg-body`, `--bg-surface` |
| Text | `--text-body`, `--text-title` |
| Border and shadow | `--border-primary`, `--shadow-primary` |
| Status | `--success`, `--error` |
| Neutral | `--light`, `--dark` |
| Typography scale | configured `--text-*` variables |
| Spacing scale | configured `--space-*` variables |

Radius, motion, focus, width, breakpoint and layer token families are required
before authors can govern those values as design tokens. Until those families
exist, a component may use an implementation-owned constant only when the value
is not exposed as an author choice.

## Document metadata

Component metadata and document metadata have different owners. Components
produce body semantics. The document publisher produces `html` and `head`.

Published documents provide:

- `<!DOCTYPE html>`;
- a language on the `html` element;
- UTF-8 and responsive viewport metadata;
- a page title and description with site fallbacks;
- a favicon when configured;
- canonical and robots metadata;
- Open Graph and Twitter preview metadata;
- language-alternate links when configured;
- the page-specific Content Security Policy.

The site General settings own the public origin, language, default title,
description and social image. A page's **SEO settings** dialog owns optional
overrides. Resetting that dialog removes the page overrides and returns to the
site defaults.

| Field | Published output | Fallback |
|---|---|---|
| SEO title | `title`, `og:title`, `twitter:title` | page title, then site name |
| SEO description | `meta[name=description]`, `og:description`, `twitter:description` | site description |
| Canonical URL | `link[rel=canonical]`, `og:url` | configured public origin plus page route |
| Indexing policy | `meta[name=robots]` | `index,follow` for public pages |
| Social image | `og:image`, `og:image:alt`, `twitter:image`, `twitter:image:alt` | page override, then site image and alternative |
| Social type | `og:type` | `website`, or an approved content type |
| Alternate languages | `link[rel=alternate][hreflang]` | configured locale routes only |
| Structured page entity | validated JSON-LD or visible microdata | omit when required properties are incomplete |

The publisher accepts an absolute HTTP(S) author value or a root-relative path,
resolves relative paths through the configured public origin, rejects unsafe
schemes and escapes all values at the HTML boundary. Canonical and social URLs
must resolve to absolute HTTPS URLs in production. Preview documents always
publish `noindex, nofollow, noarchive`, regardless of the public page policy.

## Structured data

Structured data mirrors visible content. It is never an author-editable JSON
escape hatch. The renderer derives it from governed component fields and Media
Library metadata, uses `https://schema.org` identifiers and omits incomplete
entities.

### Navigation

Site navigation publishes as a labelled navigation landmark and declares its
Schema.org type:

```html
<nav
  data-instatic-component="navigation"
  aria-label="Primary"
  itemscope
  itemtype="https://schema.org/SiteNavigationElement"
>
  <ul>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
```

The component uses a native list and anchors. Current-page state uses
`aria-current="page"`. Multiple navigation regions require distinct labels.

### Breadcrumb

Breadcrumbs publish an ordered list. Each item supplies `name`, `item` and
`position`; the last link carries current-page state.

```html
<nav data-instatic-component="breadcrumb" aria-label="Breadcrumb">
  <ol itemscope itemtype="https://schema.org/BreadcrumbList">
    <li
      itemprop="itemListElement"
      itemscope
      itemtype="https://schema.org/ListItem"
    >
      <a itemprop="item" href="/">
        <span itemprop="name">Home</span>
      </a>
      <meta itemprop="position" content="1">
    </li>
    <li
      itemprop="itemListElement"
      itemscope
      itemtype="https://schema.org/ListItem"
    >
      <a itemprop="item" href="/news" aria-current="page">
        <span itemprop="name">News</span>
      </a>
      <meta itemprop="position" content="2">
    </li>
  </ol>
</nav>
```

The author controls labels and destinations. Position and structured-data
attributes are renderer-owned.

### Image

Every published Image keeps `alt`, intrinsic dimensions, responsive sources,
loading, decoding and fetch-priority behavior. It also identifies the asset as
an `ImageObject` with `contentUrl` and the Media Library caption when present.

Licensing enhancement is emitted only when the asset model has the required
rights metadata. The complete entity may add:

- `license`;
- `acquireLicensePage`;
- `creator.name`;
- `creditText`;
- `copyrightNotice`.

The Media Library is the source of truth for alternative text and reusable
asset metadata. Per-instance context must still determine whether an image is
informative or decorative.

## JavaScript enhancement matrix

JavaScript is self-contained vanilla code, delegated from stable
`data-instatic-*` hooks and safe to initialise more than once.

| Runtime level | Entries |
|---|---|
| No JavaScript required | text, headings, links, images, tables, lists, cards, navigation, breadcrumbs, downloads, native media and ordinary form controls |
| Progressive enhancement | `creator-signal.site.catalogue.tabs`, `creator-signal.site.catalogue.form-tabs`, `creator-signal.site.catalogue.carousel`, `creator-signal.site.catalogue.dialog`, `creator-signal.site.catalogue.drawer`, `creator-signal.site.catalogue.form-container`, `creator-signal.site.catalogue.wizard` |
| Capability runtime | `creator-signal.site.catalogue.search`, `creator-signal.site.catalogue.structured-content-list`, `creator-signal.site.catalogue.file-attachment`, `creator-signal.site.catalogue.save-draft`, `creator-signal.site.catalogue.delete-draft`, `creator-signal.site.catalogue.captcha`, `creator-signal.site.catalogue.embed`, `creator-signal.site.catalogue.form-embed`, `creator-signal.site.catalogue.map`, `creator-signal.site.catalogue.youtube-embed` |

If enhancement fails, content remains readable and native controls remain
usable. A capability-backed component additionally presents its documented
unavailable or degraded state.

## Author and visitor acceptance

An entry is complete only when all applicable evidence exists:

1. The catalogue exposes only governed fields, variants, presets and slots.
2. Canvas output and published output preserve the same content and behavior.
3. Published HTML matches the semantic structure in this document.
4. Component CSS uses native data hooks and defined framework variables.
5. Keyboard, focus, naming, announcement, contrast and reduced-motion checks
   pass for the component behavior.
6. No-JavaScript and unavailable-capability fallbacks are usable.
7. Breadcrumb and applicable image structured data pass syntax validation.
8. Document metadata is correct for public, draft, preview and private routes.
9. Desktop and mobile browser checks cover the rendered DOM, computed styles,
   keyboard interaction and accessible names.
10. Live URL inspection is completed separately after deployment; local source
    and unit tests do not establish indexing or rich-result eligibility.
